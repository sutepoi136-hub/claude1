# シナリオ(会議)の追加・修正ガイド

「準備中」の話を埋めるときの手順と、データの書き方。まず物語の設定資料を読むこと。

- 仕事編: [story-work.md](story-work.md)
- 魔王軍編: [story-maou.md](story-maou.md)

## 1. 手順
1. 設定資料の「全12話の構成」で、その話の日付・難易度・決まること/保留になることを確認する(必要なら資料を先に直す)。
2. `js/data/<series>/epNN.js` を作る(既存の話をコピーするのが早い)。`id` は `work-04` のように「シリーズ-2桁の話数」。
3. `index.html` の「物語とシナリオ」の並びに `<script src="js/data/<series>/epNN.js"></script>` を、話数の順に1行足す。
4. 前後の話の `synopsis`(これまでのあらすじ)を見直す。いままで「あらすじで補っていた」出来事が、新しい話で語られるようになるため。
5. `npm test` を実行し、すべて通ることを確かめる。

## 2. 難易度の目安(テストで確認される)
| 難易度 | 参加者 | 台本の文字数 | 要点の数 | 引っかけ | 会議の作り |
|---|---|---|---|---|---|
| 初級 | 3〜4人 | 700〜1,800字 | 8〜13 | 1〜2 | 進行役が「〜に決定します」「〜は保留とします」と言い切る。訂正は1つまで |
| 中級 | 4〜5人 | 1,000〜2,600字 | 11〜16 | 2〜4 | フィラー・言い直し・数字の訂正・途中参加。締めのまとめは一部だけ |
| 上級 | 5〜7人 | 1,800〜4,000字 | 14〜20 | 3〜5 | 決定の撤回・条件付きの決定・担当の変更・結論が最後。まとめは無い |

共通: 決定事項・ToDo・保留・次回予定を必ず含める。**会議の途中で無関係な話題に脱線させない**(冒頭のあいさつ程度は可)。

## 3. データの書き方

```js
root.GQ.Data.addEpisode({
  id: 'work-04', series: 'work', no: 4, chapter: 1, level: '初級',   // 章の難易度と一致させる
  title: 'PoC計画',                                                    // 設定資料の plan の題と一致させる
  meeting: { name: '…', date: '2026-10-27', time: '10:00〜11:00', place: 'オンライン会議' },
  cast: ['柴田', '中川', '三浦', '小野寺'],     // 参加者(シリーズの登場人物から)。表示の並び順
  synopsis: '…',                               // これまでのあらすじ(会議前に表示)
  focus: ['…', '…'],                           // 記録のポイント(ヒント。答えを言わない程度に)
  script: [
    ['柴田', '…'],                             // [話者, 発言]。{player} はプレイヤーの名前になる
    ['@join', '高木'],                         // 途中参加(この行より前は「未参加」表示)
    ['@leave', '魔王'],                        // 途中退席
  ],
  points: [ /* 要点(下記) */ ],
  traps: [ /* 引っかけ(下記) */ ],
  model: `…`,                                  // 模範解答。採点すると100点になること
  epilogue: { kind: 'chat', title: '…', messages: [{ from: '柴田', to: 'DM', text: '…' }] },   // 仕事編
  // epilogue: { kind: 'scene', title: '…', text: ['段落', '段落', …] },                        // 魔王軍編
  checks: {
    alt: `…`,                                  // 模範解答とは別の書き方の解答(90点以上で、引っかけに掛からないこと)
    traps: { 'trap-id': '・引っかけに掛かる書き方の例' },   // すべての引っかけについて用意する
  },
});
```

### 台本の表記
- 数字は算用数字(「10月13日」「4分30秒」「1,350件」)。時刻は「10時」「14時」。台本で「10:00」とは書かない(読み上げが不自然)。
- 英字の略語や読み間違えやすい語は、`series.js` の `readings` に読みを足す(表示はそのまま、音声だけ置き換わる)。
- 1つの発言は300字未満。長い発言は、話者を同じにして2行に分けてよい。

### 要点(points)
| 項目 | 意味 |
|---|---|
| `type` | `decision`(決定)/ `todo` / `pending`(保留・未決)/ `issue`(課題・リスク)/ `info`(共有事項)/ `next`(次回予定) |
| `must` | `[[語, 語], [語]]`。**グループごとに1語以上が、議事録の同じ1項目(1行・箇条書き1つ)に含まれれば「書けた」**。書き方の揺れ(同義語・言い換え)を各グループに並べる |
| `owner` / `due` | ToDoの担当者・期限の語。プレイヤーが担当なら `owner: ['@player']`(名前・読み・「自分」「PMO」「書記官」などで書ける) |
| `list: true` | 「対象は3つ」のように、数行の箇条書きに分けて書かれやすい要点 |
| `weight: 2` | 重要な要点(配点2倍) |
| `trap` | `pending` の要点に付けると、「決定のように書いた」場合の引っかけを自動で作る(`trapUnless` で例外の語を足せる) |
| `why` | 結果画面に出す解説 |

照合の前に、表記は自動でそろう: 「10月13日」→「10/13」、「十一月」→「11月」、「15時」「午後3時」→「15:00」、「六十万円」→「600000円」、全角→半角、カタカナ→ひらがな、空白は無視。数字で始まる/終わる語は、前後に数字が続く場合は一致しない(「8日」は「28日」に一致しない)。

**テストの「根拠チェック」**: `must` の各グループ、`owner`、`due` のどれか1語は、必ず台本(正規化後)に出てくること。台本にない語だけで要点を作らない。

### 引っかけ(traps)
```js
{ id: 'trap-47', label: '影響件数を「47件」と書いている', why: '…52件に訂正されました。',
  when: [['47']], unless: ['52', '訂正', '当初', '→'] }
```
- 議事録の1項目に `when` の各グループの語がそろい、`unless` の語が1つも無いと反応する。
- `scope: 'decision'` を付けると、【決定事項】の下か「決定・承認」などの語がある項目だけを見る(「C案に決定」のような誤りを拾い、「C案を推奨案として提案」は拾わない)。
- 訂正された数字の引っかけは、`unless` に正しい数字と「訂正」「当初」「→」を入れておくと、「当初47件→52件に訂正」と正しく書いた人を減点しない。

### 採点の配点(js/core/scorer.js)
網羅40 / 分類15 / ToDo15(担当0.5+期限0.5)/ 正確性20(引っかけ1つ−7、要点が半分未満なら比例して減る)/ 構成10(見出し・基本情報・箇条書き・長さ)。

## 4. 物語の書き方
- 仕事編はリアル重視: 実在しそうな数字・会議の進め方・役職の言葉づかい。社名・製品名は架空のものにする。
- 魔王軍編はドラマ重視: ただし会議の形(決定・ToDo・保留・次回)は崩さない。感情の山場も、議題の中で起こす。
- 「その後」(epilogue)で、保留事項のその後や、次の話への伏線を見せる。
